# Маруська — Telegram-бот для группового чата

AI-собеседник на Gemini, рейтинг участников и «действия» с картинками
(пиво, обнять, цветы) для групповых чатов Telegram.

---

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env             # заполнить ключи
export $(grep -v '^#' .env | xargs)

python bot.py
```

Docker:

```bash
docker build -t maruska .
docker run --env-file .env maruska
```

Проверить распознавание действий без запуска бота:

```bash
python test_actions.py
```

## Команды

- `/bonus` — ежедневный бонус, `/balance` — баланс
- `/history` — последние операции, `/rich` — топ богачей
- `/level`, `/achievements`, `/toplevel` — опыт, достижения, топ
- `/fortune` (или «Мара, предскажи») — предсказание
- `/shop`, `/buy <товар>`, `/gift <товар>`, `/inventory` — магазин и подарки
- `/settings` — админ-панель: включить или выключить функции в группе
- `/myid` — узнать свой числовой ID для `OWNER_IDS`
- `/features` — что сейчас включено, без кнопок
- `/start`, `/help`, `/ping`
- `/weather Прага` — погода; без города берётся `DEFAULT_CITY`
- `/crocodile` (или просто «крокодил») — начать раунд игры
- `/stopgame` — остановить раунд
- `/profile` — ранг, рейтинг, место, статистика
- `/top` — глобальный топ-10
- `+` / `-` реплаем — плюс или минус в карму (кулдаун 24 часа на пару)
- Позвать по имени («Мара, ...») или ответить на её сообщение — AI-ответ
- «Мара, погода в Праге?» — погода без команды
- Реплаем короткое слово («Пиво», «Обнять», «Розы») — действие с картинкой

## Действия

Больше 200 действий в `actions/catalog_data.py`, сгруппированы по
категориям: `alcohol`, `drink`, `food`, `sweet`, `fruit`, `flower`,
`gift`, `pet`, `call` (дурка, скорая, такси, пожарные) и `pair`
(обнять, целую, на ручки, погладить, баня, рыбалка, селфи...).

Фразы лежат в `actions/phrases.py` — по несколько вариантов на каждую
категорию и на каждое парное действие, выбираются случайно, поэтому
одно и то же «Пиво» дважды подряд выглядит по-разному. Глагол
согласуется с родом: «Люда напоила», «Стас напоил», а если род
определить не вышло — «напоил(а)».

Синтаксис шаблона: `{actor}`, `{target_acc}`, `{target_dat}`,
`{target_gen}`, `{target_instr}`, `{item}`, `{item_instr}`,
`<угостил|угостила>`. Предмет всегда подставляется в винительном
или творительном падеже — в шаблонах не должно быть конструкций,
требующих именительного.

Добавить действие — одна строка в таблице:

```python
A("mojito", "🍹", "mojito mint cocktail", "мохито", "alcohol",
  "мохито", "мохито", "mojito|mint|cocktail"),
```

Интим, 18+ и насилие в каталог не входят.

## Скорость ответа

Три вещи, которые съедали секунды на каждую реплику, и что с ними
сделано:

1. **Размышления Gemini.** У моделей Gemini 3 `thinking_level` по
   умолчанию `HIGH` — модель долго рассуждает перед ответом. Для
   болтовни это не нужно: выставлен `low` через `GEMINI_THINKING`.
   Если модель или версия SDK параметр не знает, он тихо отключается
   после первой ошибки и бот продолжает работать.
2. **Чтение истории из базы.** Перед каждым ответом шёл запрос за
   последними сообщениями. Теперь контекст живёт в памяти
   (`context_cache.py`), а база читается один раз на чат после
   перезапуска.
3. **Запись в базу.** Сохранение пользователя и сообщения ушло в
   фоновую задачу и больше не задерживает ответ.

Плюс бот сразу показывает «печатает…», так что ожидание не немое.

Если после этого задержка осталась — посмотри, в одном ли регионе
находятся сервис на Railway и база. Разные континенты дают сотни
миллисекунд на каждый запрос.

## Болтливость

Мара, которая отвечает на каждое обращение и никогда не молчит,
в живом чате быстро надоедает. Поэтому есть три режима (`/settings`):

- **Сдержанная** — отвечает по имени, но не чаще раза в две минуты
- **Обычная** — отвечает всегда, когда обращаются (по умолчанию)
- **Болтливая** — плюс изредка вмешивается сама, без обращения

## Приветствие и итоги

**Приветствие.** Когда в чат добавляют человека, Мара здоровается и
показывает четыре команды для начала. Ловится и служебное сообщение
о добавлении, и событие `chat_member` — так что заход по ссылке-
приглашению тоже не пропускается.

**Итоги недели.** Раз в неделю (по умолчанию воскресенье, 17:00 UTC)
бот подводит итог: кто был активнее, кто больше заработал, кто чаще
выигрывал. Рассылка идёт только по живым чатам — тем, где на этой
неделе кто-то писал, и только если за неделю набралось хотя бы
десять сообщений. Вручную — `/digest`.

Недельный счётчик живёт в `group_members` и сбрасывается сам при
смене номера недели, без отдельной задачи очистки.

**`/mydays`** — сколько человек уже в этом чате и сколько написал.

## Кубики и мелочи

- `/dice 2d6`, `/dice 3d20+5` — броски, понимает и кириллические «к», «д»
- `/coin` — монетка
- `/random чай, кофе, пиво` или `/random 1 100` — выбор за тебя
- `/8ball вопрос` — шар предсказаний

Логика бросков вынесена в `games/dice_core.py` без Telegram, чтобы
её можно было тестировать отдельно.

## Взаимодействие настроек

Обращение к боту («Мара, …», упоминание, ответ на его сообщение)
проверяется отдельно от настройки «Ответы Мары». Погода и котики
вызываются тем же обращением, но живут по своим флагам — выключение
AI не должно молча убивать их. За это отвечают две разные функции
в `bot.py`: `is_addressed()` и `should_answer()`.

## Логи

Строки раскрашены по уровню: зелёный со значком ✅ — нормальная
работа, жёлтый ⚠️ — предупреждение, красный ❌ — ошибка, критическое
идёт белым по красному. Railway понимает ANSI-коды и показывает
цвет как есть.

Шум aiogram про каждое обработанное сообщение приглушён: строки
вида «Update id=… is handled» больше не заполняют вывод. Настройка
в `logging_setup.py`, отключить цвет — `LOG_COLOR=0`.

## Опыт, уровни, достижения 🎚

Опыт — не то же самое, что алмазы. Алмазы копятся редко и тратятся,
опыт копится постоянно и не тратится никогда: он показывает, сколько
человек прожил в чате.

Поэтому опыт капает и за обычные сообщения — но с потолком 120 в
сутки, чтобы уровень нельзя было выбить флудом. Награды за игры,
бонус, подарки и лайки потолком не ограничены.

Порог уровня растёт квадратично: второй — 100 опыта, третий — 300,
десятый — 4500. У уровней есть звания от «Новичка» до «Легенды чата».

**20 достижений** в шести группах: общение, уровни, серии бонусов,
деньги, игры, магазин. Одно секретное. За каждое капают алмазы —
от 20 за первое сообщение до 1000 за месячную серию.

Добавить достижение — одна запись в `progress/achievements.py`:
условие описывается функцией от словаря статистики, который уже
собирается из профиля. Ни миграций, ни новых счётчиков.

Точка входа одна — `progress.service.award()`: начисляет опыт,
проверяет достижения, выдаёт награды и возвращает, о чём сообщить
в чат. Любое новое событие подключается одной строкой.

## Характер Мары

Пять режимов: добрая, весёлая, дерзкая, романтичная, тролль.
Выбирается на уровне группы в `/settings`, так что в одном чате
Мара может быть ласковой, а в другом — язвой.

Технически меняется только кусок системного промпта: базовые
правила (язык, длина ответа, контекст) общие для всех характеров.
Добавить новый — одна запись в `ai/personas.py`, в панели он
появится сам.

Это первая настройка-список, а не переключатель. Под неё в реестре
появился тип `Choice`: значение хранится строкой, панель открывает
подменю с вариантами. Следующие настройки такого рода добавляются
одной строкой в `CHOICES`.

## Предсказания 🔮

«Мара, предскажи» (а также «погадай», «что меня ждёт»). Спрашивать
можно сколько угодно. Шестьдесят процентов шуточных, сорок серьёзных.

Последние двенадцать выданных текстов запоминаются на человека и
временно исключаются из выборки, так что подряд одно и то же не
выпадет. Когда свежие кончаются, круг начинается заново.

## Магазин и подарки 🛍

27 товаров в пяти категориях: подарки, украшения профиля, особые,
приколы и редкие. Цены от 5 💎 за мусор до 15 000 💎 за метеорит.

- `/shop` — каталог кнопками, покупка в один тап
- `/buy роза` — покупка командой, понимает и название, и ключ
- `/gift роза` реплаем — подарок, списывается с дарителя
- `/inventory` — что накопилось; подарки показаны отдельно, с именем дарителя

Купленное лежит в таблице `inventory`, количество в профиле.
Списание идёт через `change_balance`: если не хватает — покупка не
проходит и бот говорит, сколько не достаёт.

Добавить товар — одна строка в `economy/shop.py`.

## Алмазы 💎

Валюта бота. Копится только двумя способами — ежедневный бонус и
победы в играх. За обычные сообщения ничего не начисляется: иначе
экономика превращается в поощрение флуда.

**Ежедневный бонус** — случайная сумма 50–150 💎, одна попытка в
сутки. С вероятностью 5% вместо неё выпадает джекпот 300–500 💎.
Работает по команде `/bonus` или коротким «бонус» в чате.

**Серия** считается по календарным дням UTC: продлевается, только
если прошлый бонус был ровно вчера. Любой пропуск обнуляет. На
размер выплаты серия не влияет, она для азарта — показывается
огоньками в профиле и лучший результат тоже запоминается.

**Награды за игры**: победа в Крокодиле 25 💎, ведущему 15 💎.
Начисляются только если экономика включена в группе.

Каждая операция пишется в `transactions` вместе с балансом после
неё, поэтому `/history` читается как выписка и ничего не нужно
пересчитывать. Начисление и списание идут одной транзакцией с
блокировкой строки профиля — параллельные запросы не разъедутся.

Списание через `change_balance` с отрицательной суммой: если денег
не хватает, операция не проходит и возвращает текущий баланс. Это
основа для будущего магазина и подарков.

Суммы настраиваются переменными окружения, балансировать можно без
правки кода.

## Веб-панель

`/settings` → кнопка «🖥 Веб-панель». Открывается как Mini App прямо
в Telegram.

**Вход без пароля — намеренно.** Публичная админка с паролем рано
или поздно подбирается. Здесь Telegram сам сообщает, кто пришёл,
подпись проверяется ключом бота, а подделать её нельзя. Человек
видит только те группы, где он администратор; владельцы бота из
`OWNER_IDS` — все.

Проверка администраторства дёргает Telegram, поэтому результат
кэшируется на пять минут: иначе каждый чих в панели превращался бы
в пачку запросов.

Что есть в первой версии:

- **Главная** — участники, сообщения, алмазы, опыт и график
  активности за 7, 14 или 30 дней
- **Настройки** — все 27 параметров: тумблеры, выпадающие списки,
  шаговые счётчики и поля для текстов
- **Люди** — список с уровнем, балансом, опытом, кармой, временем
  последней активности и поиском по имени
- **Группы** — где бот работает, сколько участников,жив ли чат

Под графики появилась таблица `daily_stats`: `message_memory`
обрезается, а недельные счётчики обнуляются каждый понедельник,
так что для истории нужна отдельная.

### Что нужно настроить один раз

`/newapp` в BotFather ещё раз: тот же бот, название «Панель»,
Web App URL `https://<домен>/admin`, short name `admin`. Затем в
Railway переменная `WEBAPP_ADMIN_NAME=admin`.

Пока она пуста, кнопка в `/settings` просто не показывается —
всё остальное работает как раньше.

## Админ-панель

`/settings` в группе — кнопки-переключатели по разделам.
`/features` показывает текущее состояние списком.

### Кто имеет доступ

По умолчанию — администраторы той группы, где вызвана панель
(проверка через `get_chat_member`).

Чтобы настройки мог менять только ты, задай `OWNER_IDS`:

1. Напиши боту `/myid` — он ответит твоим числовым ID.
2. Добавь в Railway переменную `OWNER_IDS=<этот ID>`.

После этого админы групп доступ теряют, а ты можешь менять настройки
в любой группе, где есть бот. Несколько владельцев — через запятую.

### Как добавить новую функцию

Одна строка в `settings/registry.py`:

```python
Feature(
    key="memes",
    title="Мемы",
    emoji="😂",
    description="Мара кидает мем по запросу",
    group="Развлечения",
    default=False,
),
```

и одна проверка в коде функции:

```python
if not is_enabled(message.chat.id, "memes"):
    return False
```

Всё: переключатель появится в панели сам, миграция базы не нужна —
значения лежат в JSON-колонке, незнакомые ключи берут значение
по умолчанию.

**Забыть подключить не получится.** `test_settings.py` сверяет реестр
с исходниками: если функция объявлена, но нигде не проверяется через
`is_enabled()`, тест падает с конкретным именем ключа. Работает и в
обратную сторону — проверка несуществующего ключа тоже ошибка.

### Как это устроено

Настройки читаются на каждое сообщение, поэтому ходить в базу из
фильтров нельзя. Значения кэшируются в памяти (`settings/store.py`),
а прогревает кэш внешняя мидлварь (`settings/middleware.py`) — она
отрабатывает раньше фильтров, так что выключенная функция не успеет
сработать.

В личке ограничений нет: настройки существуют для групп.

## Крокодил

Написать в группе «крокодил» — начинается раунд.

- Ведущим становится победитель прошлого раунда. Если раунд первый,
  ведущего выбирают кнопкой «Я ведущий».
- Ведущий жмёт «🎨 Рисовать» — открывается холст прямо в Telegram.
  Слово написано вверху и видно только ему. Рисунок уходит в чат.
- Есть кнопки «Другое слово» (если попалось неудобное) и «Сдаюсь».
- Первый, кто написал слово в чат, побеждает. Падежи засчитываются:
  «кошку» подойдёт за «кошка».
- Таймера нет: раунд живёт до отгадки, сдачи или `/stopgame`.
- Победителю и ведущему по +1 к рейтингу, счётчики игр в профиле
  тоже растут.

### Из референсов

- **«🖐 Хочу рисовать!»** — кнопка под итогом раунда. Ход может
  забрать любой, не дожидаясь, пока победитель напишет «крокодил».
  Раньше игра вязла, если победитель отошёл.
- **Табло подсказок** — под рисунком появляется поле с ячейками,
  как в «Поле чудес»: `▢ ▢ ▢ ▢ ▢ ▢ ▢ ▢`. Кнопка открывает по одной
  букве, между буквами пауза 30 секунд (`HINT_COOLDOWN`), больше
  половины слова открыть нельзя. Просить подсказку может любой,
  кроме ведущего — он и так знает слово.
- **«🎨 Дорисовать»** — открывает холст с предыдущим рисунком, можно
  продолжить поверх, а не начинать заново.
- **«👍 Лайк»** под рисунком. Один человек — один лайк, свой рисунок
  лайкать нельзя. Художнику капает 1 💎 за каждый.
- **Живое обновление.** Пока ведущий рисует, холст раз в несколько
  секунд отправляет кадр, и сообщение в чате обновляется на месте:
  зрители видят, как рисунок рождается. Кадр уходит только если с
  прошлого раза что-то изменилось, так что лишнего трафика нет.

Словарь — 271 слово трёх уровней в `games/words.py`. Сложные
выпадают реже, чтобы игра не буксовала.

Активные раунды держатся в памяти (`games/state.py`) — фильтр
сообщений должен быть быстрым. База остаётся источником правды:
после перезапуска незакрытые раунды подтягиваются обратно.

Во время раунда обычная переписка работает как всегда: перехватывается
только верная отгадка.

## Холст (Mini App)

Рисование живёт в `webapp/`: `server.py` — aiohttp рядом с ботом,
`static/draw.html` — сама страница с холстом (кисть, восемь цветов,
четыре толщины, отмена, стирание).

Кнопка в группе ведёт на ссылку вида
`t.me/<бот>/<short_name>?startapp=<токен раунда>`. Обычные web_app-кнопки
Telegram разрешает только в личке, а такая прямая ссылка открывается
из любого чата.

Каждый запрос со страницы несёт `initData` от Telegram, сервер
проверяет его подпись ключом бота и сверяет, что открывший холст —
действительно ведущий этого раунда. Без этого чужой мог бы
подсмотреть слово или подсунуть свой рисунок.

### Что нужно настроить один раз

1. В Railway включить публичный домен: Settings → Networking →
   Generate Domain. Порт сервис берёт из `PORT` автоматически.
2. В BotFather: `/newapp` → выбрать бота → название, описание,
   картинка → Web App URL: `https://<домен>/draw` → short name,
   например `draw`.
3. В Railway добавить переменную `WEBAPP_SHORT_NAME=draw`.

Пока `WEBAPP_SHORT_NAME` пуст, игра работает словесной версией:
слово показывается ведущему во всплывающем окне, он объясняет
текстом. Всё остальное одинаково.

Проверить, что сервер поднялся: открыть `https://<домен>/` —
должен ответить `{"ok": true}`.

## Котики

«Мара, покажи меня» (а также «какой я», «кто я», «мой портрет») —
портрет собеседника в виде котика. «Мара, мяу» (или «мур», «кис-кис») —
просто котик без привязки к человеку, со своим набором подписей.

Двенадцать «настроений» — хмурый, удивлённый, зевающий, в коробке,
в очках, вверх лапами — каждое отдельной коллекцией. Отбор жёсткий:
требуются теги `cat`, `kitten` или `kitty`, а 23 тега отсекаются —
львы, тигры и рыси (у них тоже тег «cat»), собаки, рисунки, векторы,
логотипы и статуэтки. Настроения, исключения и подписи в
`actions/show_me.py`.

## Когда действие НЕ срабатывает

Главная защита от флуда: в сообщении не должно быть ничего, кроме
самого действия. «Пиво» — команда, «тоже хочу пиво» — реплика в
разговоре, и бот туда не лезет.

Разрешены только служебные слова («а», «ну», «мне», имя бота) и
глаголы намерения из `ACTION_VERBS` — «угости пивом», «налей водки»,
«вызвал дурку» работают. Любое постороннее слово отменяет действие.

Без этого бот встревал в чужие диалоги: чей-то ответ «Тоже кошку»
превращался в подарок котёнка.

## Погода

Open-Meteo, ключ не нужен и лимитов для чата нет. Два запроса:
геокодинг названия города и прогноз. Отвечает текущей температурой,
ощущаемой, влажностью, ветром и прогнозом на завтра.

Город вытаскивается из фразы («погода в Праге» → Праге), при неудаче
берётся `DEFAULT_CITY`. Коды погоды WMO разложены в эмодзи и описания
в `weather.py`.

## Источники картинок

По умолчанию — **Pixabay**. Его лицензия атрибуции не требует, поэтому
под фото ничего не подписывается. Лимит 100 запросов за 60 секунд на ключ,
но с кэшем в базе реальных обращений почти нет: коллекция набирается один
раз и дальше крутится из Postgres.

**Ссылки Pixabay одноразовые.** Они подписаны и живут около суток —
сложить их в базу и использовать через день нельзя, придёт
`400 Bad Request`. Поэтому в базе не хранятся ссылки вообще: только
`photo_id` и `telegram_file_id`.

Как работает подбор:

1. Есть в коллекции картинка с готовым `file_id` — отправляем её.
   Мгновенно, без обращения к источнику.
2. Коллекция пуста или исчерпана — ищем в Pixabay и **сразу**
   скачиваем, пока ссылка жива. Отправляем байтами, полученный
   `file_id` кладём в базу.
3. Источник молчит — прокручиваем собранное по кругу.

Со временем коллекция набивается `file_id`, и Pixabay почти не
опрашивается. Скачивание идёт с внятным `User-Agent`: без него
Pixabay тоже отвечает 400.

**Unsplash** остался запасным источником и по умолчанию выключен. Его
лицензия атрибуцию требует, поэтому у его картинок подпись сохраняется.
Включается через `IMAGE_PROVIDERS=pixabay,unsplash`.

Релевантность обеспечивают обязательные теги: у каждого действия в
таблице задан список фрагментов, и фото засчитывается, только если
хотя бы один из них есть в его тегах. Без этого по запросу
"couple kissing" прилетает свадебный пейзаж, по "vodka" — небоскрёб,
а по "burger" — ягоды.

Фильтр не отключается никогда. Если строгий поиск ничего не дал,
запрос упрощается — от точной фразы к ключевому слову и в конце к
самому тегу ("burger juicy" → "burger" → "hamburger"), но требование
к тегам остаётся. Лучше ответить «картинки пока нет», чем прислать
не то.

Ключ коллекции содержит отпечаток правил: `pixabay/burger#aab4ee`.
Меняешь запрос или теги действия — отпечаток меняется, и картинки,
набранные по старым правилам, автоматически перестают использоваться.
Чистить базу руками не нужно.

Коллекции хранятся отдельно по источнику и комбинации пола:
`pixabay/hug:male_female`. Поэтому при смене источника старые картинки
просто перестают использоваться, ничего чистить не обязательно.

## Что исправлено

### Критичное

1. **Ложные срабатывания действий.** Старый `find_action` искал алиас как
   подстроку в любом месте текста, поэтому «о**пять**», «по**вод**»,
   «вы**сок**ий», «г**ром**ко», «**суп**ер» запускали действие — и это же
   сообщение не доходило до AI-хендлера. Теперь действие распознаётся только
   как короткая фраза (≤3 значимых слова), совпадение идёт с начала слова с
   ограниченным хвостом, для двусмысленных слов требуется точное совпадение,
   плюс стоп-лист. Покрыто тестом `test_actions.py`.

2. **Фейковые пользователи из ветки `@username`.** `get_user_by_username`
   возвращала ORM-объект, у которого `.id` — автоинкремент строки, а не
   Telegram ID. Дальше этот `.id` писался в `users.telegram_id`. Введён
   единый `Target` с явным `telegram_id`.

3. **Утечка соединений к базе.** Повсеместный `async for session in
   get_session()` с `return` внутри оставлял асинхронный генератор
   незакрытым. Заменено на `async with session_scope()`.

4. **`get_me()` на каждое сообщение.** ID и username бота теперь читаются
   один раз при старте.

5. **Приоритет роутеров.** Действия вынесены в отдельный роутер, включённый
   перед основным, с синхронным фильтром, который проверяет и наличие
   адресата. Костыль `not is_action_message(...)` в AI-хендлере убран:
   «Пиво» без реплая теперь просто уходит в обычный чат, а не проваливается
   в пустоту.

### Остальное

- Род глагола по имени: «Люда угостила», «Стас угостил» вместо
  «угостил(а)». Латиница тоже распознаётся — `STANISLAV` определяется
  как мужской род по списку и транслитерации.
- Поисковые запросы Unsplash переписаны на тёплые и позитивные.
  `people supporting each other` отдавал депрессивную документалку —
  теперь `friends cheering each other up smiling`.
- Кэш `telegram_file_id`: фото отправляется по ссылке один раз, дальше
  мгновенно из Telegram. Битые ссылки удаляются из коллекции.
- `datetime.utcnow()` → `utcnow()` без предупреждений (наивный UTC,
  миграция базы не нужна).
- `get_rating_stats` — один запрос вместо четырёх.
- Гонка при выдаче картинки закрыта `FOR UPDATE SKIP LOCKED`.
- Модель Gemini, лимит токенов и температура вынесены в окружение.
- Ответ модели отправляется с `parse_mode=None`, чтобы случайные `<` и `>`
  не роняли отправку.
- Добавлены индексы, логирование, корректное закрытие сессии и пула,
  `Dockerfile`, `Procfile`, `.env.example`, `.gitignore`, `ai/__init__.py`.

```

fortune.py              предсказания

features/               то, что видит пользователь
  basic.py              /start, /help, /ping
  chat.py               разговор с Марой и болтливость
  rating.py             плюсы, минусы, профиль, топ
  weather.py            погода
  cats.py               «покажи меня» и «мяу»
  fortune.py            предсказания
  greeting.py           приветствие новых участников
  digest.py             итоги недели и «сколько я здесь»

actions/                205 действий с картинками
games/                  крокодил, кубики
economy/                алмазы, магазин, подарки
progress/               опыт, уровни, достижения
settings/               админ-панель и реестр функций
```

Правило простое: `bot.py` не растёт. Новая функция — новый модуль
в `features/` или отдельный пакет, если она крупная.
