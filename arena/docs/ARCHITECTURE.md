# Маруська Арена — архитектура

Онлайн-дурак для реальных игроков Telegram внутри экосистемы бота Маруська.
Сервер решает всё: раздачу, чей ход, законность каждой карты, итог и деньги.
Клиент показывает состояние и отправляет намерения.

## 1. Что уже есть в репозитории и что из этого следует

| Факт | Решение |
|---|---|
| Бот написан на **Python** (aiogram 3 + aiohttp) и работает одним процессом на Railway: long polling плюс веб-сервер на `PORT` для Mini App «Рыбалка» и «Крокодил». | Арену **не встраиваем** в Python-процесс. Это отдельный Node/TypeScript-сервис в папке `arena/`, отдельный сервис на Railway. Бот продолжает работать как раньше. |
| В `public` уже есть таблицы `users`, `transactions`, `user_achievements` (алмазы, достижения бота) со своей структурой. | Все таблицы арены живут в **отдельной схеме `arena`** той же PostgreSQL. Ни одна таблица бота не меняется, конфликтов имён нет. Миграции Prisma и их служебная таблица `_prisma_migrations` тоже лежат в `arena`. |
| Проверка Telegram initData уже написана в `webapp/server.py`, `fishing_api.py`. | Та же схема HMAC повторена в `apps/api/src/telegram/initData.ts` с проверкой срока и тестами на подделку. |
| Алмазы 💎 бота хранятся в `public.user_profiles.coins` и меняются через `SELECT … FOR UPDATE`. | На первом этапе у арены **своя валюта** (фишки для ставок, монеты, алмазы-резерв) со своим журналом. Мост «алмазы бота ↔ арена» делается отдельно, через идемпотентный обмен (этап 5). Так ошибка в арене не может испортить экономику бота. |
| `Dockerfile` бота делает `COPY . .` | Добавлен корневой `.dockerignore` с `arena/`: образ бота не растёт и не тащит Node-код. |
| `test_imports.py` импортирует все `.py` рекурсивно. | Папка `arena/` и `node_modules` исключены: там встречаются чужие `.py`. |

### Замечания к ТЗ

* **Команда `/игра` в меню невозможна.** Telegram допускает в командах только латиницу, цифры и `_`. Поэтому в меню бота стоит `/game` (и `/durak`), а «/игра» ловится как текст. В личке также срабатывают «игра», «играть», «дурак». В группах бот откликается только на явные фразы вроде «в дурака», чтобы не засыпать чат кнопками и не перехватывать отгадки «Крокодила».
* **Восемь «режимов» — это на самом деле четыре пары переключателей:** Подкидной/Переводной, Все/Соседи (кто подкидывает), Честная/С шулерами, Классика/Ничья (исход, когда последний отбился последней картой). Комната хранит все четыре значения, а фильтр лобби ищет по любому из них. Все четыре пары уже поддержаны движком.
* **Deep link `t.me/<бот>?startapp=…`** открывает только *главное* Mini App бота (BotFather → Bot Settings → Configure Mini App). Если арена будет не главным приложением, ссылка должна иметь вид `t.me/<бот>/<short_name>?startapp=game_<id>`. `roomDeepLink()` в `@arena/shared` строит оба варианта.
* **Ставки до 10M и «баланс».** Валюта виртуальная и не выводится. Любая продажа фишек за Telegram Stars и тем более вывод денег превращают игру в азартную с юридической точки зрения. До такого решения монетизация — только косметика.
* **Название.** Предлагаю «**Маруська Арена**»: оно не привязано к одному дураку, и под ним можно добавлять другие игры. Название задаётся в одном месте (`index.html`, заставка).

## 2. Схема взаимодействия

```
 Telegram-клиент
   │  /game → кнопка «🎮 Играть» (web_app) или t.me/<бот>/<app>?startapp=game_<id>
   ▼
 Mini App (React, apps/web)  ──HTTPS──►  Arena API (Fastify, apps/api)  ──►  PostgreSQL, схема arena
   │   initData → POST /api/auth/telegram  │  проверка HMAC, upsert user,          (users, wallets, transactions,
   │   ◄── session token (HS256, 24 ч)     │  бонус новичку (идемпотентно)          rooms, games, game_moves…)
   │                                       │
   └──WSS /ws?token=… (этап 2)────────────►│  Room/Game manager  ──►  Redis
                                           │   · game-engine (чистые функции)       (живое состояние комнат,
                                           │   · таймеры ходов                        presence, pub/sub между
                                           │   · журнал ходов в game_moves            инстансами, локи)
                                           │
 Бот Маруська (Python) ◄──────────────────┘  outbox notifications / Bot API sendMessage
   · кнопка «Играть», приглашения, итоги партий
```

* **Идентичность.** Единственное доказательство личности — подписанная Telegram строка `initData`. Сервер проверяет подпись токеном бота, срок (`INIT_DATA_MAX_AGE_SECONDS`), создаёт или обновляет пользователя и выдаёт короткий токен сессии. Никакой `userId` от клиента не принимается.
* **Один источник правды.** Состояние партии хранится только на сервере (память процесса + снапшот в Redis). Клиент получает `PlayerView`: свою руку, число карт у соперников, стол, козырь, число карт в колоде и список разрешённых действий.
* **Бот ↔ арена.** Арена кладёт уведомления в таблицу `notifications` (outbox). Доставлять их может сама арена через Bot API тем же `BOT_TOKEN` (`sendMessage` не конфликтует с long polling бота) или бот через `/internal/*` с `INTERNAL_API_SECRET`. Приглашения в комнату — это ссылки `startapp=game_<roomId>`, которые Mini App разбирает после авторизации (`AuthResponse.startParam`).

## 4. Игровое ядро (`packages/game-engine`)

Файлы: `Card`, `Deck`, `Rules`, `GameState`, `Actions`, `TurnManager`, `AttackManager`, `DefenseManager`, `TransferManager`, `GameEngine`, `PlayerView`, `Scoring`.

```ts
applyAction(state, playerId, action, now) → { ok: true, state, events } | { ok: false, error }
applyTimeout(state, now)                  → ход «за игрока», когда истёк таймер
legalActions(state, playerId)             → { attack[], defend{card→targets}, transfer[], take, pass }
toPlayerView(state, viewerId)             → то, что можно отправить этому игроку
settle(result, players, stake, rake%)     → выплаты
```

`applyAction` — чистая функция: входное состояние не меняется, а отклонённый ход ничего не применяет наполовину. Случайность приходит извне (`Random`): на сервере криптографическая, в тестах с зерном. Поэтому партию можно воспроизвести по сохранённой колоде и журналу ходов.

**GameState:** `gameId, version, status, phase (attack|defense|taking|finished), rules, players[{id, seat, hand, status, place}], deck, trump{suit, card}, table[{attack, defense, by}], discard, attacker, defender, currentPlayer, boutLimit, boutNumber, passed[], turnDeadline, finishOrder, winner, loser, result`.

Правила взяты из присланного описания игры (см. также экран «Правила» в приложении):

* Колода 24, 36 или 52 карты (2–Т), 2–6 игроков (для 24 карт — до 4). По 6 карт, козырь — последняя карта колоды, первым ходит младший козырь, ход по часовой стрелке.
* Ходить можно одной картой или несколькими картами одного достоинства (`PLAY_CARDS`).
* Подкидывать можно достоинства, которые уже есть на столе. Не больше, чем может побить защитник, и не больше 6 (до первого отбоя — 5).
* **Право подкидывать:** сначала только атакующий. После его «Бито» право переходит в режиме «Соседи» к следующему за защитником, в режиме «Все» — ко всем остальным. Новое достоинство от защитника сбрасывает «Бито», и право возвращается атакующему.
* «Беру»: остальные ещё подкидывают (кто не хочет — «Пас»), затем защитник забирает стол, а ходит следующий за ним. Всё отбито и все сказали «Бито» — карты уходят в отбой, ходит отбившийся.
* Добор: главный атакующий, затем остальные по часовой стрелке, защитник последним.
* Переводной: пока защитник не начал биться, можно положить карту того же достоинства и перевести ход на следующего, если тот сможет ответить на все карты. Перевод проверяется строго даже в режиме «с шулерами».
* **С шулерами:** подкидывать и биться можно любыми картами. Какие карты незаконны, знает только сервер (`state.illegal` в `PlayerView` не попадает). Любой другой игрок может указать на карту (`REPORT_CHEAT`). Если она незаконна, она и все карты, сыгранные после неё, возвращаются владельцам, а автор попадает в `cheaters` и до конца игры играет по правилам. Указание на честную карту ничего не меняет.
* **Поражение:** последний игрок с картами, а также сдавшийся («Сдаться» = `LEAVE_GAME`) или не успевший сходить. Таймаут атакующего, который должен начать ход, или защитника перед небитыми картами — это поражение. Подкидывающим, которые просто не нажали «Бито»/«Пас», сервер нажимает кнопку сам.
* Если последнюю карту отбили последней картой: «Ничья» — ничья, «Классика» — дурак тот, кто подкинул последнюю карту. **Этот случай в присланных правилах не описан, его нужно подтвердить.**
* **Вернуть карту** (за монеты): `undoLastMove(before, after)` возвращает последнюю карту, пока никто не сходил после неё и не закончился отбой.
* **Подсветка** (за монеты, для премиума бесплатно): без неё `PlayerView.actions` содержит только признаки «можно ходить / бить / переводить» для кнопок, а списки подходящих карт пусты. Это удобство, а не секрет: модифицированный клиент может вычислить их из своей руки. **Напомнить отбой:** `PlayerView.discard` отдаётся только с этой опцией; эти карты все игроки и так видели.

### Рейтинг, лиги, бонусы (`packages/shared/src/rating.ts`)

* Прирост = `10 · log2(1 + выигрыш) · 5000 / (5000 + рейтинг) · бонус · премиум`. Выигрыш 1000 даёт в ≈1,5 раза больше, чем 100. На высоком рейтинге тот же выигрыш даёт меньше.
* 6 лиг (серебряная, золотая, рубиновая, изумрудная, сапфировая, Высшая) по 16 уровней. Стоимость уровня растёт: `100 + 10·i` очков. Каждые 4 уровня — звезда, остаток — полосы, плюс процент до следующего уровня.
* Бонус постоянного игрока: раз в 20 часов одна победа умножается; множитель растёт на 1 за каждый полученный бонус (от ×2 до ×30) и сбрасывается после 44 часов без игр. Сияние по серии: 7 — жёлто-красное, 14 — зелёное, 21 — синее, 28 — пурпурное.
* Премиум: победитель с премиумом получает ×2, остальные за его столом — ×1,5. Столы с премиум-игроками идут первыми в лобби, подсветка для них бесплатна.
* Доска почёта: сортировка по рейтингу, выигрышу или победам (остальные два поля — тай-брейк). Сезон: `seasons` + `season_ratings`, рейтинг с нуля.
* Все числа собраны в `RATING`, их можно настраивать.

### Экономика

* **Кредиты** (`CREDITS`) — ставки и выигрыши. **Монеты** (`COINS`) — «вернуть карту», «отбой», «подсветка», косметика. Цены — в `FEATURE_PRICES`. Алмазы зарезервированы под мост с ботом.
* 1450 кредитов бесплатно раз в сутки, если на счету меньше 1450 (`POST /api/wallet/daily-credits`). Строка кошелька блокируется, так что параллельные нажатия дают одно начисление. Стартовый бонус — те же 1450.
* Вывести кредиты через намеренный проигрыш нельзя: тип транзакции `MODERATION` для изъятия модератором, блокировка — `users.banned_at/banned_until` (бессрочная, если `banned_until` пуст). Автоматический поиск сговора (одни и те же пары, систематический проигрыш крупных ставок) — этап 8.

Тесты (47): отдельные правила и **800 случайных полных партий** на 2–6 игроков с колодами 24/36/52, в том числе «с шулерами» с доносами. В каждом ходе проверяется, что все карты на месте, дублей нет, лимиты соблюдены, в честной игре нет незаконных карт и партия заканчивается. Ещё 8 тестов покрывают рейтинг, лиги и бонусы.

## 5. База данных (Prisma, схема `arena`)

`users` (telegram_id UNIQUE, блокировки) · `profiles` (рейтинг, выигрыш, премиум, бонус) · `wallets` (user, currency) UNIQUE, `CHECK balance >= 0` · `transactions` (idempotency_key UNIQUE, `CHECK balance_after = balance_before + amount`) · `rooms` · `games` (initial_deck для аудита) · `game_players` · `game_moves` (append-only, UNIQUE (game, seq)) · `game_results` · `friends` (двунаправленно) · `friend_requests` · `items` · `user_items` · `achievements` · `user_achievements` · `tournaments` · `tournament_players` · `notifications` (outbox для бота) · `seasons` · `season_ratings`.

### Деньги (`services/ledger.ts`)

Баланс меняет только `Ledger.post()`:

1. Внутри одной транзакции БД выполняется условный `UPDATE wallets SET balance = balance + x WHERE … AND balance >= -x`. Строка блокируется до коммита, поэтому двойная трата невозможна.
2. В той же транзакции пишется строка `transactions` с `balance_before/after`, типом, источником и `idempotency_key`.
3. Повтор с тем же ключом, даже одновременный, откатывается на UNIQUE и получает в ответ первую запись.
4. Ни один маршрут не принимает сумму от клиента: суммы берутся только из правил сервера (ставка комнаты, расчёт `settle`).

Интеграционный тест: 25 одновременных списаний по 1000 с баланса 10 000 — ровно 10 проходят, 15 получают `INSUFFICIENT_FUNDS`, итоговый баланс 0. Восемь одновременных одинаковых выплат зачисляются один раз.

Ставки (этап 5): при старте партии — `GAME_STAKE:<gameId>:<userId>` для всех игроков одной транзакцией; в конце — `GAME_PAYOUT:<gameId>:<userId>` по `settle()`; при сбое сервера — `GAME_REFUND`. Комиссия берётся только из ставки дурака.

## 6. WebSocket-протокол (`packages/shared/src/protocol.ts`)

Один сокет на клиента: `/ws?token=<session>`. Сообщения клиента проверяются zod-схемой; у каждого может быть `rid`, и сервер отвечает `ACK` или `ERROR` с тем же `rid`.

Клиент → сервер: `PING, LOBBY_SUBSCRIBE, LOBBY_UNSUBSCRIBE, ROOM_WATCH, READY, RECONNECT{roomId, lastVersion}, PLAY_CARD{gameId, card, target?}, PLAY_CARDS{cards}, TRANSFER, TAKE_CARDS, PASS, LEAVE_GAME («Сдаться»), REPORT_CHEAT{seq}, UNDO_MOVE, USE_FEATURE{hints|discardReminder}, SEND_EMOJI`.

Сервер → клиент: `LOBBY_SNAPSHOT, ROOM_CREATED, ROOM_UPDATED, ROOM_REMOVED, ROOM_JOINED, ROOM_LEFT, GAME_STARTED, GAME_STATE (персональный PlayerView), GAME_EVENTS (CARD_PLAYED, CARD_TRANSFERRED, CARDS_TAKEN, ROUND_FINISHED, PLAYER_TURN, CARDS_DRAWN — только количество…), GAME_FINISHED, PLAYER_CONNECTED, PLAYER_DISCONNECTED{graceUntil}, PLAYER_RECONNECTED, ERROR, PONG`.

Каждый игрок получает **свой** `GAME_STATE`. Карты соперников, порядок колоды и содержимое отбоя с сервера не уходят (это проверяет тест `player view`). `version` растёт с каждым принятым ходом: клиент отбрасывает устаревшие состояния, а после переподключения запрашивает снимок.

Реконнект: при обрыве игрок помечается `disconnected`, соперники получают `PLAYER_DISCONNECTED` со сроком ожидания, партия продолжается по таймерам. Вернувшись, клиент отправляет `RECONNECT` и получает полный `GAME_STATE`.

## 7. Серверная часть realtime (`apps/api/src/realtime`)

| Модуль | Отвечает за |
|---|---|
| `ws.ts` | `/ws?token=`: проверка сессии, heartbeat каждые 25 с, пересылка сообщений в `Realtime` |
| `realtime.ts` | разбор и проверка сообщений (zod), лимит 10 сообщений/с на сокет, повтор с тем же `rid` не выполняется дважды, восстановление после перезапуска |
| `hub.ts` | один живой сокет на пользователя (новая вкладка вытесняет старую, код 4002), подписки на лобби с фильтром |
| `rooms.ts` | комнаты: создание, вход по паролю или коду из ссылки, «Готов» (30 с на полную комнату), быстрая игра, 30 с на возврат в комнату ожидания, передача хозяина |
| `games.ts` | одна партия = один `GameRunner` с последовательной очередью: ходы, таймер хода, «вернуть карту», подсветка, отбой, смайлики, журнал ходов, персональные состояния |
| `store.ts` | снимки комнат и партий: Redis (`REDIS_URL`) или память |
| `services/settlement.ts` | ставки при старте (одна транзакция), итог партии (одна идемпотентная транзакция): выплаты, статистика, рейтинг, бонус, сезон, достижения |

Порядок гарантирован: всё, что меняет комнату или партию, идёт через её `SerialQueue`. Два одновременных хода, таймер и покупка «вернуть карту» не могут перемешаться.

После перезапуска комнаты и партии поднимаются из Redis, таймеры перезапускаются, игроки переподключаются и получают полное состояние. Если Redis нет и партию продолжить нельзя, ставки возвращаются (`GAME_REFUND`), а партия помечается `ABORTED`.

REST: `GET /api/rooms?stakes=&players=&deckSizes=&speeds=&modes=`, `POST /api/rooms`, `POST /api/rooms/quick`, `GET /api/rooms/:id`, `POST /api/rooms/:id/join {password|invite}`, `POST /api/rooms/:id/leave`, `GET /api/me/active`, `GET /api/games/:id`.

Ссылка-приглашение: `t.me/<бот>/<app>?startapp=game_<КОД>_<invite>`. `invite` — HMAC от кода комнаты, поэтому по ссылке пароль не нужен, а без неё нужен.

Тесты (`test/multiplayer.test.ts`) гоняют ботов по настоящему WebSocket: полные партии на двоих и троих, скрытые карты, переподключение посреди партии, попытки сыграть чужую карту, «Сдаться», приватные комнаты, быструю игру и перезапуск сервера с продолжением партии через Redis.

### Анимации стола (`apps/web/src/screens/game/motion.ts`)

Когда приходят `GAME_EVENTS`, DOM ещё показывает старое состояние: `MotionDirector` запоминает положение каждой карты (`data-card`). После отрисовки нового `GAME_STATE` каждая карта плавно переезжает со старого места на новое (FLIP). Новые карты вылетают из места соперника или из колоды. Ушедшие (в руку соперника, в отбой) заменяются летящими копиями. Анимируются только `translate`/`scale`/`opacity`, так что работает GPU. Выключаются настройкой «Анимации карт» и системным «уменьшить движение».

Звуки синтезируются WebAudio: ни одного файла, мгновенно на медленной сети. Звук, вибрация, анимации и сортировка руки — в «Настройках» и сохраняются на устройстве.

### Друзья и уведомления через бота

`services/friends.ts` отвечает за заявки, дружбу, поиск и приглашения, `services/notifier.ts` — за очередь сообщений бота. Если адресат в сети, он получает событие по WebSocket (`FRIEND_REQUEST`, `FRIEND_ACCEPTED`, `ROOM_INVITE`). Если нет — в таблицу `notifications` пишется сообщение, и арена отправляет его через Bot API тем же `BOT_TOKEN` с кнопкой-ссылкой в Mini App. С long polling Python-бота `sendMessage` не конфликтует. Неудачные отправки повторяются фоновой задачей до 5 раз, а тем, кто не запускал бота или заблокировал его, сообщения больше не шлются.

Внутренний API для бота (`Authorization: Bearer $INTERNAL_API_SECRET`): `GET /api/internal/players/:telegramId` (рейтинг, лига, победы — для /profile бота) и `GET /api/internal/stats` (онлайн, партии, открытые столы).

## 8. Масштабирование

* Движок не хранит ничего в глобальном состоянии, а партия — это данные. Её можно сериализовать в Redis и продолжить на другом инстансе.
* Каждая комната закреплена за одним инстансом (владельцем) через Redis-лок `room:<id>:owner`. Лобби и присутствие хранятся в Redis, изменения рассылаются через pub/sub. «Серверы» (Алмаз, Рубин…) уже записываются в каждую комнату, так что позже их можно разнести по отдельным пулам инстансов.
* PostgreSQL получает только редкие записи: создание комнаты, старт и конец партии, журнал ходов пачками, деньги. Горячая часть работает в памяти и Redis.
